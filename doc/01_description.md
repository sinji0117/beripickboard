# 01. 설명 — beripickboard (베리픽보드)

> 문서 버전: v0.0.1 · 작성일: 2026-10-31

## 1. 한 줄 정의
**그누보드5 · 영카트5 · 이윰보드4(EB4)의 구조와 DB를 그대로 계승하면서, 실행 엔진만 Rust(Axum) + React 19로 교체한 CMS.**

## 2. 왜 만드는가
| 기존(PHP) 한계 | beripickboard의 해결 방식 |
|---|---|
| 요청마다 PHP 전체 부트스트랩(common.php) → 트래픽에 약함 | Axum 비동기 서버 상주 + Redis 캐시 |
| 스킨/테마가 PHP·HTML 혼합 → 유지보수·보안 취약 | React 19 컴포넌트 테마, API와 화면 분리 |
| MyISAM 테이블 → 트랜잭션 없음, 주문·포인트 정합성 리스크 | InnoDB 전환 + 트랜잭션 처리 |
| 보안 패치가 개별 사이트에 적용 안 되는 경우 다수 | 단일 바이너리 배포, 버전 관리 |

## 3. 핵심 원칙 (결정 사항)
1. **g5 스키마 호환** — `g5_member`, `g5_board`, `g5_write_{bo_table}`, `g5_shop_*`, 이윰보드 테이블의 **테이블명·컬럼명·값의 의미를 바꾸지 않는다.** 기존 DB를 연결하는 것만으로 이전이 끝나는 것이 목표.
2. **신규 기능만 신규 테이블** — 라이센스, 위젯 배치, 토큰 등 g5에 없는 것은 `bp_` 접두사 테이블에 둔다. g5 테이블에 컬럼을 추가하지 않는다(여분 필드 `wr_1~10`, `mb_1~10`은 사용자 데이터이므로 건드리지 않음).
3. **파일 경로 호환** — `data/file/{bo_table}/`, `data/editor/`, `data/item/`, `data/member/`, `data/member_image/` 구조를 그대로 사용한다.
4. **비밀번호 호환** — g5의 PBKDF2(`sha256:12000:salt:hash`) 및 구형 MySQL `PASSWORD()` 해시로 그대로 로그인된다.
5. **공존 가능** — 이전 기간 동안 PHP 사이트와 beripickboard가 같은 DB를 바라보며 동시에 운영될 수 있어야 한다.

## 4. 범위
- 그누보드5: 회원·그룹·게시판·댓글·포인트·쪽지·스크랩·투표·내용관리·FAQ·1:1문의·방문자·인기검색어·메뉴·팝업
- 영카트5: 상품·분류·옵션·장바구니·주문·쿠폰·배송비·후기·문의·이벤트·배너·개인결제·PG
- 이윰보드4: 테마·레이아웃·EB 콘텐츠/슬라이더/최신글(위젯)·메뉴·회원 레벨/활동·태그 등 확장 기능
- 독자 기능: **라이센스 등록·도메인 정품 인증**(이윰보드 방식)

## 5. 기준 버전
| 대상 | 기준 버전 | 근거 |
|---|---|---|
| 그누보드5 | 5.6.44 | github.com/gnuboard/gnuboard5 `version.php` |
| 영카트5 | 5.4.5.5.1 | 동일 저장소 `G5_YOUNGCART_VER` |
| 이윰보드4 | 설치본 기준 확정 필요 | 실제 운영 DB `SHOW TABLES LIKE '%eyoom%'`로 확정 |

구버전 사이트는 g5의 `migrations/` 와 동일한 순서로 스키마를 먼저 최신화한 뒤 연결한다(→ 03, 14 문서).
